# 一票ください — 迷った二択に、知らない誰かが数分で票をくれる

## 最重要: セキュリティと個人情報 (持ち主の指定、2026-11-26)
持ち主:「こういう投稿できる系はセキュリティ対策と、個人情報の扱い（利用規約など）、が超重要です。ここをちゃんとやることを最重要なチケットにする」

- **計画はこれを最優先の task にする** (最初の版の計画で、ほかの機能の task より先に作る)。ここが全部済むまで、誰でも使える状態で公開しない (ship しない)
- **利用規約** (画面からいつでも読める): 書いてはいけないこと (自分や他人の名前・住所・電話・メール・学校や勤め先・SNS の ID など個人が分かること、誹謗中傷、違法な内容、宣伝)、運営ができること (投稿の非表示・削除、利用の停止)、免責、使える年齢、規約を変えるときの知らせ方
- **プライバシーポリシー** (画面からいつでも読める): 集めるもの・集めないものの一覧 (このアプリの「守り」の欄と同じ)、使い道、置く場所 (Cloudflare)、残す期間と消え方、第三者に渡さないこと、問い合わせ先
- **同意**: 初めて使うときに、規約とポリシーへの同意を 1 回だけもらう (読めるリンクつき)。変えたときはもう一度
- **個人情報を書かせない仕組み**: 送る前に、電話番号・メールアドレス・URL・SNS の ID・住所らしいものを見つけたら止める (端末とサーバーの両方で検査する)
- **セキュリティ**: 入力は全部検査して上限をかける、生の HTML を差し込まない・CSP、Origin の検査、送る回数の上限 (同じ人・同じ回線)、機械的な大量投稿の対策、セキュリティのヘッダ、依存の脆弱性の検査、ログに投稿の中身や IP を残さない
- **テスト**: 上のどれも受け入れテストで確かめる (個人情報らしい文は送れない、上限を超えると止まる、規約に同意しないと投稿できない、など)。誰のデータに届くかの仕様とテスト (認可) は機能を足すたびに
- **消す**: 自分の投稿は自分でいつでも消せて、消したら本当に消える (残る期間があればポリシーに書く)
- **問い合わせ先** (持ち主の決定、2026-11-26:「問い合わせフォームにしよう」): アプリの中の問い合わせフォーム。持ち主の名前・メールは公開しない。返事が要る人だけ返信先を任意で書く
  - 届け先は、工場のアプリと分けた問い合わせ専用の非公開 repo (例 `wakuwaku-inbox`) の issue。持ち主は GitHub の通知で受け取る
  - 間違って公開されないように: issue を作る前に毎回その repo が非公開かを確かめ、公開なら送らずに止める (持ち主:「まちがえて公開されるとかがちょっとこわい」)。工場はこの repo の公開・設定を変えない
  - issue を作る権限は、その repo の issue だけを書ける GitHub App。鍵は Cloudflare の秘密の設定に置く (手元に置かない)。repo と App を作るのは持ち主の許可を取ってから (wk human)
  - 問い合わせの本文に IP などを足さない。フォームにも送る回数の上限

## 概要
小さなことで迷ったら、二択を投げる。知らない人たちが数分のうちに票を入れてくれて、理由は一言だけ添えられる。自分も、ほかの人の迷いに一票を返せる。ログインはいらない。持ち主が選んだ案 (2026-11-26)。

## わくわくポイント
「どっちのシャツ」「この LINE 送る? 送らない?」を投げると、数分で 12 対 5 になり、「青のほうが顔色よく見える」の一言がつく。背中を押されて決められる。暇なときは他人の迷いに次々と一票を返せて、小さく人の役に立てる。

## ニーズ
小さなことで迷って決められない。でも友だちに相談するほどのことではないし、聞くのは気がひける。SNS で聞くと知り合いに見られる。気軽に、知らない人の感覚を借りて決めたい。

## シーン
服屋の試着室で 2 着の写真…ではなく文字で「黒のコートか、紺のコートか (30 代・通勤用)」と投げる。会計に向かう前に 9 対 3。「紺は手持ちと合わせやすい」の一言で紺に決める。

## 体験の核
1. 二択を 10 秒で投げられる (問いと A・B だけ。ログインなし)
2. 数分で票が集まる (投げた人は、ほかの人の二択に票を返すと自分のが先に出る、の順番で回す)
3. 票と一言の理由が見える。決めたら「こっちにした」で締められ、票を入れた人にも結果が届く

## ターゲット
小さなことで迷いやすい人、背中を押してほしい人、すきま時間に人の役に立ちたい人。

## マネタイズ
なし。

## 差別化ポイント
相談サイトは重く、回答が遅い。SNS の投票は知り合いに見られ、票も集まりにくい。ここは二択と一言だけに絞り、「票を返すと自分のが先に回る」形で、知らない人の票が数分で集まる。

## デザイン (持ち主の指定、2026-11-26)
- **カード型** (UI モックの案 C)。タブは「答える・聞く・マイページ」
- **答えるは 1 枚ずつスワイプ** (持ち主:「答えるのカードはYoutubeのショート動画や、Ticktokみたいに、一枚ずつスライドのUXにして。単純なスクロールじゃなくて」): 1 画面に 1 枚、上にスワイプで次の二択 (scroll-snap で 1 枚ずつ止まる)
- **マイページ** (持ち主:「自分のに択ってなに。単純にマイページ的なのでいいのでは。アカウント設定も込みで」): 聞いたことの一覧 (割合の帯・人数・残り時間・決めた方)。タップすると結果と理由、押すと「こっちにした」。下に設定 (利用規約・プライバシーポリシー・お問い合わせ・この端末のデータを削除)。ログインなしなので、マイページはこの端末だけ
- **聞く**: 迷っていること (40 字)・A と B (15 字)・ひとこと (任意 25 字)・時間 (1・6・24 時間)。そろうまで「聞く」は押せない
- 理由の一言は、答えた人が票のあとに任意で書く (30 字)。多いときは新しい順
- 見本は同じフォルダの ui-mock.html (決まったら置く)

## 守り
- ログインなし。IP アドレスは残さない。ひとり 1 票の見分けは、IP を毎日変わる鍵で変換した値だけ (元に戻せない)
- 文字だけ (写真なし)。問い・選択肢・理由に短い上限。生の HTML を差し込まない
- 二択と票は一定時間 (例: 24 時間) で消える
- 通報と自動の非表示、回数の上限をかける。外部のスクリプト・解析・広告を入れない
