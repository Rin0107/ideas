上から順に確かめる。1 つでも NG なら `request_changes`。

## 1. セキュリティ (最優先。1 つでも当てはまれば NG)
- 新しく **持つ・送る・残す** 情報があるか。あれば DATA.md の差分に書かれているか。書かれていても、個人と結びつく情報
  (アカウント・メール・名前・住所・電話・IP・User-Agent・位置・Cookie・支払い・健康・他人や未成年の情報) なら NG
- ログイン・セッション・Cookie・トークンを作っていないか
- 外部への通信 (fetch・WebSocket・画像やフォントの外部 URL・外部スクリプト) が増えていないか。増えていれば NG
- 生の HTML の差し込み・eval・動的なコード生成・利用者の入力をそのまま使ったパスや SQL がないか (SQL は bind だけ可)
- 秘密情報 (鍵・トークン・パスワードらしき文字列) が差分にないか

## 2. テスト
- テストを消したり弱めたり、`skip` したりしていないか
- 閾値 (カバレッジ・ミューテーション) や CI の設定を緩めていないか

## 3. 依存
- 新しい依存があれば、本当に必要か・有名で保守されているか・install script がないか・版が固定されているか

## 4. 守りの部分
- 守りの部分 (`.github/` `.claude/` `scripts/` `src/worker/security.ts` `wk.json`) を変えていないか

## 5. 失敗と入力の扱い
- 入力の検査 (zod など) とサイズの上限があるか。書き込みの API が増えたなら上限 (回数・大きさ) があるか
- 失敗したとき (通信できない・保存できない・壊れた入力) に、落ちずに分かる形で止まるか。例外を握りつぶしていないか
- 手元の機械の上限 (メモリ・CPU・並列の数、`scripts/limit.sh`・`GOMAXPROCS`・`maxWorkers` など) を外していないか

## 6. CI
- CI が全部 green か (pending なら、その旨を書いて判定はコードで行う)

## 出力
次の JSON **だけ** を出す (前後に文章を書かない):
```json
{"verdict": "approve", "issues": [], "summary": "1〜2 文"}
```
`verdict` は `approve` か `request_changes`。`request_changes` のときは `issues` に、直すべきことを 1 件 1 文で、具体的に (ファイル名と何をどうするか)。
