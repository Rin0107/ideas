# intake — アイディアを足し、磨く

## 1. 材料を読む (読むだけ)
- これまでの結果: `state/portfolio.json`、`reports/evaluations/`、drop の理由 (idea.md の `## 履歴`)
  → **何が ship され、何がなぜ捨てられたか** から、通りやすい形を学ぶ
- ユーザーの関心: `~/src/okuos/me/goals.md`、`~/src/okuos/reports/growth/` の最新 1 件
  (ユーザーの日記や会話のログは読まない。個人的な内容をアイディアに持ち込まない)

## 2. 新しいアイディアを 5 件書く
`ideas_wakuwaku/idea-template/idea-template.md` の形で、`ideas_wakuwaku/<次の ID>-<slug>/idea.md` に。
`ideas_wakuwaku/INDEX.md` の末尾にも 1 行ずつ足す (形式: `- <ID> <slug> — 一言(わくわくの核)`)。
次の ID は既存の最大 + 1 から順に。
- 採用条件は「わくわくすること」。そして **重要な情報を持たずに成立すること** (ブラウザの中だけ・匿名の集計だけ)
- 実在の企業・作品・人物になりすまさない。既存の有名なゲームや作品の再現にしない
- 「体験の核」は 1 つに絞り、静的ファイルだけの Web (サーバーなし) か Go の CLI で作れる形で書く
- 既存と重ならない (タイトル・slug・中身)。`wk check` が形と重複を検査する

## 3. 既存の未着手のアイディアを 3 件磨く
`wk candidates -n 30` から、点が付きにくそうなもの (核がぼやけている・重要な情報が要る形) を 3 件選び、
体験の核を絞る・ブラウザの中で完結する形に変える。`## 履歴` に「磨いた: 何を」を 1 行。

## 4. 検査して終える
```bash
wk check
```
通るまで直す。leader に報告する。note は「intake: 新規 5 件・磨き 3 件」。
